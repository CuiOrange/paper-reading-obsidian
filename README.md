# Paper Reading Obsidian

将指定论文收录到 Zotero 的适当分类，通过 ZotLit 创建 Obsidian 文献笔记，再生成有原文定位、公式推导和带注释代码的中文精读内容。

## 安装

仓库根目录就是技能目录。发布到 GitHub 后，支持技能安装器的客户端可直接接收仓库链接。也可把完整目录复制到客户端的技能目录；例如 Codex 的 `~/.codex/skills/paper-reading-obsidian`，或 Claude Code 的 `~/.claude/skills/paper-reading-obsidian`。目录中应直接包含 `SKILL.md`。

本地维护时可创建符号链接，避免两份文件漂移：

```bash
ln -s /absolute/path/to/paper-reading-obsidian ~/.codex/skills/paper-reading-obsidian
```

目标已存在时先检查，不覆盖原技能。安装后在下一轮对话查看是否已发现技能；未发现时重新开启会话。

## 依赖和能力

- Obsidian 桌面版、Zotero，以及 ZotLit 插件。
- 模板资源按已检查的 ZotLit 2.1.4 文件式 Liquid 接口编写；其他版本先检查其实际模板或 profile 格式。
- 自动收录需要实际可用的 Zotero 写入接口或 UI 操作能力；ZotLit 创建笔记也需要可调用的真实操作。技能本身不会提供这些连接。
- 检查脚本只需要 Python 3.10+ 标准库；全文提取按环境选用 PyMuPDF、现有转换器或 PDF 工具。
- 已安装 `anti-defensive-writing`、`shuorenhua` 时读取并遵循；没有时使用包内的基本写作规范。

安装技能不会替换现有模板、启用 CSS、修改主题或改动文库。首次配置时确定目标文库、vault、模板位置、论文笔记目录、分类映射和待分类位置，再验证一次真实的创建及更新流程。

## 使用

```text
使用 $paper-reading-obsidian 收录并精读这篇论文：https://arxiv.org/abs/...

继续完善这篇论文的笔记，重点补全损失函数与作者代码的对应关系。

只解释笔记中的定理 2，保留我的其他内容。
```

默认写中文，明确要求英文时使用完整对应的英文流程、标题、图注和代码注释。Obsidian 文件中的公式使用 `$...$` 和 `$$...$$`；聊天中的公式遵循用户指令。论文主线、完整证明和代码分层组织，长内容可折叠。作者论断、补充推导和个人思考分别标明。

## 论文笔记结构

每篇论文使用一个方法名文件夹，主文件同名。沿用参考 skill 的三部分内容结构，第二部分可按需拆到同层附加笔记：

```text
Papers/方法名/
├── 方法名.md       # 完整讲解与讲解附录；仅保留必要文献属性
├── 附加笔记.md     # 按需：第二部分完整证明、长推导和实验细节
└── images/
```

主笔记属性只保留 `title`（标题）、`authors`（作者列表）、`venue`（会议／期刊／arXiv）、`code`（已核实的代码仓库）和 `year`（年份）。未知值直接省略。删除 Zotero、条目身份、citekey、分类、阅读状态、日期、阅读路线等属性。正文摘要之后只保留一个 Zotero 跳转和一个“论文原文”链接，不再并列添加 PDF、DOI、arXiv 等重复入口；附加笔记通过正文链接返回主笔记。

标题仅在文件名和 `title` 属性中保留，正文不再另写一层笔记名标题。主笔记正文开头使用展开的 `> [!abstract] TL;DR` callout，完整、准确地翻译所读版本的原文摘要，保留限定条件、数字与术语，不缩写成概要、不加入讲解者评价。随后直接进入不编号的内容章节，不加“第一部分”层级；需要保留的 Zotero 批注作为可见正文放在后部。

主笔记按七个不编号的一级标题组织：不用公式讲解 → 前置知识 → 方法概述 → 实验 → 讨论 → 附录 → 思考。方法概述下以二级标题组织问题设定与总览、各个组件（理论论文为主要结果）；实验下以二级标题组织主实验和消融。方法定位、符号表、版本差异、错误检查、参考文献及其作用都放在同一个“附录”一级标题下，作为二级标题，不再独立并列。标题名称可按论文调整，层级和顺序保持一致。主要实验表格、原图和实质性消融留在主笔记，简短的注释代码放在对应方法旁。

第二部分包括完整证明、长推导、全部超参数、训练评估细节和补充实验。内容较多时放入 `附加笔记.md`，否则放在对应方法附近或附录中折叠展示，不增加新的顶层章节；可选的是分文件，不是省略细节。“附录”包含方法定位、符号表、版本差异、错误与一致性检查、参考文献及其作用，后面是保留给用户的“思考”。主笔记与附加笔记使用完整仓库相对路径互链，默认不再创建单独的“方法理解”或“实验分析”等主题文件。Zotero 分类保留在 Zotero Collection 或已有索引中，不增加笔记属性。

优先使用作者实际给出的方法/框架名；没有方法名时采用简短研究对象或短标题，不杜撰缩写。不同论文方法名相同则加年份，必要时再加条目身份；同一论文再次处理时复用原目录。插件默认文件名只是创建时的起点，实际通过受支持的移动/重命名落实最终路径，并把文献身份与路径对应关系记录在笔记外的紧凑状态中。删除原生 Zotero 属性后不再假设 ZotLit 自动定位或刷新可用，后续通过外部映射与正文链接找到原笔记，避免重复创建。

不生成 `zotero_notes/`，也不为每条 Zotero 笔记或批注导出单独 Markdown 文件。相关内容直接整理进主笔记或附加笔记并标明来源，原始记录仍保存在 Zotero；需要使用的批注图片放入该论文的 `images/`。

图片附件统一保存在与笔记同级的 `images/` 文件夹中，主笔记与附加笔记共用；包括论文原图、PDF 裁图、批注图片和讲解示意图。正文使用如 `![方法流程](images/fig-02-pipeline.png)` 的相对链接，或包含完整仓库相对路径的 Obsidian 嵌入，避免不同论文的同名图片混淆。首次保存图片时再创建该目录。

检查脚本、临时 `checks/` 文件夹、原始结果和仅供核验的截图统一放在系统临时目录中。执行后先把检查方法、必要输入、结果和适用范围简要写进现有笔记，再删除临时文件；失败时也执行清理。笔记中不保留指向已删除脚本或结果文件的链接。长任务确需断点续读时，在论文目录外复用一个紧凑状态文件，不另外生成多份清单、日志和验证报告。技能包自带的通用检查器仍保留在技能目录。

只修改 skill 不会移动既有笔记或替换当前启用的模板。

## 国际化与紧凑排版

中文请求：`精读这篇论文并存入 Obsidian，使用中文笔记，适当补充注释代码。`

English prompt: `Read this paper closely and save English notes in my Obsidian vault. Collect it in Zotero and add annotated code where verified author code is available.`

英文笔记使用 `Details.md`、`Paper`、`Return to main note` 等对应名称；中英文模板分别为 `zotlit-note.liquid.md` 和 `zotlit-note.en.liquid.md`。两种语言保持同等精读深度，不复制成两份正文。

- 原文章节引用写作 `ch III-B`、`ch 3.2`，不用章节符号，也不同时标页数。
- 正文与显示公式之间不留空行；保留标题、列表、表格所需的 Markdown 间距。
- 算法伪代码默认使用 `$$...$$` 中带行号、横线和缩进的 MathJax 格式，放在对应方法旁；[完整示例与规则](references/reading-guide.md#algorithm-pseudocode-with-line-numbers)。沿用原文算法编号，自行整理的版本标明“补充伪代码”；作者代码仍使用对应编程语言的代码块。
- 可比较的竖向图用两列或三列表格并排：首行为图片，下一内容行为说明，保留原图编号和可读性。
- 不使用“第一部分”这一层标题，所有内容标题不加序号；原文公式、图表和定理编号保留。
- 成品笔记不含 HTML 注释或 ZotLit 管理标记。通过笔记外的快照和定向合并保留用户修改。
- 术语首次出现附英文：中文讲解采用“中文译名（English original）”，之后统一使用该译名。

## 目录

- `SKILL.md`：流程入口与关键约束。
- `references/setup.md`：环境发现、接口和模板安装。
- `references/reading-guide.md`：精读、数学、实验和代码讲解。
- `references/writing-guide.md`：清晰表达与两个写作技能的调用规则。
- `references/note-contract.md`：笔记身份、内容区域、恢复状态与展示规范。
- `assets/zotlit/`：可选 Liquid 模板；安装到 vault 前适配并预览。
- `assets/paper-note.css`：仅作用于 `paper-reading` 类的可选样式。
- `scripts/validate_note.py`：只读结构检查，不能判断论文理解是否正确。

## 检查笔记

```bash
python3 scripts/validate_note.py /absolute/path/to/note.md --vault /absolute/path/to/vault \
  --paper-folder /absolute/path/to/vault/Papers/METHOD
```

脚本检查精简属性、单一正文来源链接、无隐藏标记、标题层级、公式间距、围栏闭合、模板残留及本地嵌入目标。指定 `--paper-folder` 时，默认只接受方法名主笔记和 正文带有主笔记返回链接的 `附加笔记.md`；只有用户明确要求额外拆分时才使用 `--allow-extra-notes`。主笔记是否完整解释方法仍须对照原文检查。它不完整解析 YAML/LaTeX，不模拟 ZotLit，也不代替 Obsidian 渲染和原文核验。

## 发布

此目录作为独立 Git 仓库发布。提交提示词、模板与检查器即可，个人路径配置、凭据、论文 PDF 和私人笔记不进入技能仓库。Zotero/ZotLit 的实际接口因环境而异，应分别记录已经验证和仍待接通的能力。
